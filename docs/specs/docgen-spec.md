# cino 仕様書生成仕様（ドラフト）

## 1. 対象範囲

本書は cino ソースから仕様書を決定的に生成する規則を定義する。
生成時に LLM は利用しない。

## 2. 入力

- 構文解析済み AST
- 検証済みシンボル/型情報
- メタデータ注釈

各ドメインシンボルの必須メタデータ:

- `name_ja`
- `name_en`
- 短い説明

任意項目:

- 制約条件
- カテゴリタグ（`state`, `event`, `query`, `rule`, `term`）

## 3. 出力形式

- 日本語仕様書: Markdown / HTML
- 英語仕様書: Markdown / HTML

同一入力に対しては安定した差分が得られる出力とする。

## 4. 生成規則

- セクション順序を固定する
- テンプレートベースで生成する
- AST + メタデータ以外の暗黙推論をしない

## 5. 最低限の生成セクション

- ドメイン概要
- 状態モデル
- イベント一覧
- クエリ一覧
- update 遷移規則
- Action 一覧
- 制約・不変条件

## 6. トレーサビリティ

各生成節に追跡情報を保持する。

- ソースシンボルID
- ソース位置（可能な場合）

これにより仕様書とコードの往復確認を可能にする。

## 7. 多言語整合性

- `name_ja` / `name_en` 欠落は警告（strict ではエラー）
- 用語集を日英で生成する
- 言語間でセクションIDを安定化する

## 8. CLI 契約（提案）

```text
cino docgen --in <source-or-package> --lang ja --out ./docs/ja
cino docgen --in <source-or-package> --lang en --out ./docs/en
```

strict モードでメタデータ不備がある場合は非0終了コードとする。
